Enterprise Investment Management Platform

High availability & 24x7 server model
Zero-downtime focus for batch windows

Objective

Enable a 24x7 application server that remains available during batch processing windows, while preserving correctness for date-sensitive operations (trade date, valuation date) and cache coherence.

Architecture Summary

  • Active/active cluster of application servers behind an API gateway/load balancer
  • Controlled process restart strategy (rolling restart) to apply configuration changes safely
  • Cache invalidation rules aligned to events, batch milestones, and date rollover
  • Global synchronization primitives to ensure consistent “business date” across nodes

Date Rollover (D → D+1)

Date rollover is treated as a coordinated lifecycle event, not a simple clock tick. Rollover may be triggered by a scheduler based on zone calendars, with safeguards to prevent partial transitions.

Order Eligibility Cleanup

  • Re-evaluate orders with date constraints (valid-from/valid-until, market calendar rules).
  • Expire or re-queue workflows that cannot proceed on D+1.
  • Write auditable lifecycle updates (who/what/when) for operational traceability.

Controlled Restarts

Zero downtime does not mean “never restart”. It means restarts are controlled and do not break inflight work.

  • Drain node → stop accepting new sessions → complete inflight work → restart → rejoin.
  • Use health checks and version compatibility to avoid mixed-mode failures.
This section is framed as a platform enhancement: resilience, uptime, and predictable operations.
