Batch processing framework
Orchestration, dependencies, and idempotency

Batch Families

  • Daily: pricing ingestion, valuation, reconciliations, audit rollups
  • Weekly/Periodic: maintenance, recomputation, archival/historization
  • Pricing: market data alignment, late price corrections, snapshot publication
  • Event-driven catch-up: reprocess subsets after upstream corrections

Orchestration Model

The batch engine executes parameterized jobs in a dependency graph, with safeguards that support reruns without creating inconsistent outcomes.

flowchart TD START([Start Batch Window]) --> PRE[Pre-checks: calendars, inputs, locks] PRE --> ING[Ingest pricing / reference data] ING --> VAL[Valuation & position updates] VAL --> HIST[Historization / snapshots] HIST --> PUB[Publish milestones / notifications] PUB --> END([End Batch Window]) PRE -->|failure| ABORT[Abort + alert] ING -->|late prices| ING VAL -->|retry safe| VAL

Key Design Requirements

  • Dependency sequencing: enforce prerequisites (inputs, prior jobs, zone readiness).
  • Idempotency: rerunning a job produces the same end state for the same inputs.
  • Partitioning: batch workloads can be segmented (e.g., by portfolio group, by time zone).
  • Observability: every batch step emits metrics and audit records for traceability.

Generic Command Structure (Example)

# illustrative CLI pattern (non-proprietary)
# run a batch family for a zone with an explicit valuation date
batchctl run \
  --family daily \
  --zone APAC \
  --valuation-date 2026-03-01 \
  --max-parallel 8 \
  --retry-policy per_event \
  --dry-run false
