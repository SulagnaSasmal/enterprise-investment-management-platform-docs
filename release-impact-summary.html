SunGard Asset Arena Manager

Release impact summary
Governance: ops readiness, risk, compatibility

Release Overview

This section provides an operations-ready summary of Asset Arena platform changes. It is structured for Change Advisory Board (CAB) review and operations sign-off.

Functional Impact

  • NAV batch processing becomes zone-aware, aligning valuation to fund domicile business dates.
  • Business date rollover formalized as a coordinated lifecycle event across WebLogic cluster nodes.
  • JMS failover and retry behavior becomes explicit and auditable per event in Oracle audit tables.
  • Pre-trade compliance engine extended with new UCITS concentration limit rules.

Operational Impact

  • New Splunk dashboards: NAV batch milestones per zone, audit failure rates, rollover timing
  • Updated runbooks: recovery mode activation, targeted fund reprocess, Coherence cache flush
  • Capacity planning: peak Oracle RAC load shifts as APAC/EMEA/Americas zones process sequentially
  • MQ monitoring: new DLQ alerting rules for zone-specific event processing failures

Deployment Approach

  • WebLogic rolling deployment: zero-downtime upgrade using F5 drain + restart per node.
  • Oracle schema changes via Liquibase: expand-migrate-contract pattern, backwards-compatible.
  • Feature flags: zone-based batch processing enabled per zone (APAC first, then EMEA, then Americas).
  • Rollback plan: feature flags revert to single-zone behavior; Liquibase contract step deferred.

Backward Compatibility

  • AAIM API maintains existing contract; zone parameter is optional with default to legacy single-zone.
  • FIX Gateway message format unchanged; new zone metadata added as optional tags.
  • SWIFT MT5xx generation unaffected; settlement date calculation uses existing calendar logic with zone override.

Risk Assessment

  • Incorrect zone-calendar mapping causes NAV calculation against wrong business date — mitigated by pre-batch calendar validation check.
  • Rollover timing drift across WebLogic nodes creates inconsistent business date — mitigated by atomic rollover protocol with node convergence timeout.
  • JMS retry storms under zone failure overload Oracle RAC — mitigated by MDB pool size reduction in degraded mode.
  • Late pricing for APAC zone delays EMEA batch start — mitigated by independent zone batch windows with configurable wait thresholds.

Monitoring & Alerting Requirements

  • Per-zone NAV batch: start, end, duration, success/failure count (Splunk + PagerDuty)
  • Event processing audit: status distribution, retry depth, oldest-failed event age
  • Rollover: start/end timestamps, node convergence time, cache refresh completion
  • Oracle RAC: active sessions, wait events, tablespace growth post-batch
This release impact summary is structured for CAB approval. Operations sign-off requires completed UAT, updated runbooks, and confirmed Splunk dashboard deployment.
