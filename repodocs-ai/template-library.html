Documentation Template Library

The Documentation Template Library is a curated set of Markdown templates that cover the full range of documentation types produced by SaaS API teams. Every template is structured, parameterised, and ready to fill. Templates are maintained in a docs/templates/ directory within the repository and versioned alongside the product.

Design principle: Every template enforces a consistent heading hierarchy, required sections, and a standard YAML front-matter block. Writers fill in placeholders — they do not redesign structure from scratch for each document.

Template categories

API reference

  • Endpoint reference — HTTP method, path, path/query parameters, request body, response schema, error codes, examples
  • Authentication guide — API key, OAuth 2.0, JWT bearer token, mTLS patterns
  • Webhooks reference — event types, payload schema, delivery guarantees, retry policy, signature verification
  • Error code catalogue — standardised table of error codes, HTTP status mapping, resolution steps
  • Rate limiting guide — limits per tier, headers, back-off strategies

Developer guides

  • Getting started — prerequisites, first API call, authentication, and a working example in 5 minutes
  • SDK integration guide — installation, initialisation, common operations, error handling
  • Quickstart tutorial — step-by-step walkthrough of a core use case end-to-end
  • Migration guide — version-to-version breaking changes, code diff examples, deprecation notices
  • FAQ — structured question-answer format with category grouping

Architecture & design

  • Architecture decision record (ADR) — context, decision, consequences, status, alternatives considered
  • System design document — goals, non-goals, high-level design, component interactions, open questions
  • Data model reference — entity definitions, field types, relationships, example JSON/YAML
  • Integration specification — source, destination, protocol, data contract, error handling

Operations & governance

  • Runbook — preconditions, step-by-step procedure, rollback steps, escalation contacts
  • Incident response playbook — detection, triage, containment, resolution, post-mortem
  • Changelog — version, date, added/changed/deprecated/removed/fixed/security sections
  • Release notes — audience-facing summary of changes, upgrade notes, known issues
  • SLA / SLO definition — service name, metric, target, measurement window, exclusions

Metadata Schema

All RepoDocs AI documentation files carry a YAML front-matter block validated against a shared JSON Schema. Consistent metadata enables automated indexing, status reporting, ownership tracking, and review reminders.

Required fields

title
Human-readable page title. Used in navigation, search indexes, and link previews.
description
One-sentence summary of the document. Rendered as the meta description tag.
category
Document type from the controlled vocabulary: api-reference, guide, architecture, operations, governance.
version
API or product version this document applies to. Uses semver or date-based versioning.
status
Lifecycle state: draft | review | published | deprecated.

Optional fields

tags
Array of keyword tags for search and filtering. Example: [authentication, oauth2, security].
audience
Intended reader: developer, operator, architect, executive.
owner
GitHub username or team name responsible for keeping the document current.
last-reviewed
ISO 8601 date of last editorial review. Used by staleness checks in the validation system.
related
Array of relative paths to related documentation files.
api-version
Specific API version the page documents, if different from the product version.

Complete front-matter example

---
title: "Create Payment Intent"
description: "Creates a new payment intent to initiate a charge against a customer's payment method."
category: api-reference
version: "2.4"
status: published
tags:
  - payments
  - intents
  - stripe-compatibility
audience: developer
owner: "@payments-team"
last-reviewed: "2024-11-15"
related:
  - ../guides/payment-flow.md
  - ./confirm-payment-intent.md
api-version: "v2"
---

Status lifecycle

The status field drives automated workflows in the validation system.

draft
Work in progress. Validation warnings are surfaced but do not fail the CI check. Not indexed by the documentation search.
review
Ready for peer review. Full validation runs. Requires at least one reviewer approval before merge.
published
Live documentation. Indexed by search. Changes trigger a staleness review reminder for the owner.
deprecated
Retained for reference but no longer actively maintained. A deprecation banner is rendered automatically.
The metadata schema is defined in .repodocs/schema/frontmatter.schema.json at the root of the repository. CI validates every Markdown file against this schema on every pull request.
