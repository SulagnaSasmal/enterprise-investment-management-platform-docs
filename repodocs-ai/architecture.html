AI-Native Docs-as-Code Documentation System

Supported technology stack

Documentation format

  • Markdown — primary authoring format across all templates
  • CommonMark-compatible with front-matter YAML metadata
  • MDX supported for component-augmented sites (Docusaurus)

Repository platforms

  • GitHub — primary supported platform (Actions, Pages, Copilot)
  • GitLab — planned for future release
  • Bitbucket — planned for future release

Static documentation generators

  • Docusaurus — React-based, MDX, versioned docs
  • MkDocs — Python-based, Material theme, excellent search
  • GitBook — hosted or self-hosted, git-sync workflow
  • Next.js documentation sites — custom builds with Nextra or similar

AI tooling

  • GitHub Copilot (inline prompt support)
  • OpenAI API (batch generation workflows)
  • Anthropic Claude (structured prompt framework)

System architecture

RepoDocs AI is composed of five major subsystems that work together to provide end-to-end documentation generation, validation, and maintenance. Each subsystem can be adopted independently or as part of the full system.

flowchart TD REPO[Git Repository] --> TL[Documentation Template Library] REPO --> MS[Metadata Schema] TL --> DRAFT[Draft Documentation] MS --> DRAFT DRAFT --> APF[AI Prompt Framework] APF --> GEN[AI-Generated Content] GEN --> DT[Diagram Templates] GEN --> VAL[Documentation Validation System] DT --> FINAL[Final Documentation] VAL --> FINAL FINAL --> REPO

Subsystem 1: Documentation Template Library

A curated collection of Markdown templates covering the full range of SaaS API documentation needs. Templates are parameterised with placeholder variables and structured according to industry-standard documentation conventions.

  • API reference templates (endpoint, request/response, authentication)
  • Getting started guide templates
  • Architecture decision record (ADR) templates
  • Runbook and incident response templates
  • Changelog and release note templates
  • SDK and integration guide templates

Full template library documentation →

Subsystem 2: Metadata Schema

A YAML front-matter schema applied uniformly to all documentation files. Metadata enables automated tooling to index, validate, route, and render documentation consistently across repositories.

  • Required fields: title, description, category, version
  • Optional fields: tags, audience, status, last-reviewed, owner
  • Status lifecycle: draft → review → published → deprecated
  • Machine-readable schema with JSON Schema validation support

Full metadata schema documentation →

Subsystem 3: AI Prompt Framework

A structured library of AI prompts designed for safe, high-quality documentation generation. Each prompt template includes context-setting blocks, guardrails to prevent hallucination, and output format specifications that match the template library.

  • Prompt templates for API endpoints, error codes, authentication flows
  • Context injection patterns for codebase-grounded generation
  • Guardrail rules: factual grounding, tone consistency, completeness checks
  • Human review checkpoints integrated into the generation workflow

Full AI prompt framework documentation →

Subsystem 4: Diagram Templates

A library of diagram starter templates using Mermaid.js and PlantUML, designed for the most common technical documentation diagram types. Templates embed directly in Markdown and render in GitHub, Docusaurus, MkDocs, and GitBook.

  • Flowchart templates (API request flow, data pipeline, event-driven architecture)
  • Sequence diagram templates (authentication, webhooks, batch processing)
  • Entity-relationship (ER) diagram templates
  • State machine templates (resource lifecycle, order status)
  • C4 architecture diagram templates (context, container, component)

Full diagram templates documentation →

Subsystem 5: Documentation Validation System

An automated quality gate that runs in CI to enforce documentation standards before changes are merged. The validation system checks structure, metadata completeness, internal link integrity, and prose quality using configurable rules.

  • YAML front-matter schema validation against the metadata schema
  • Internal and external link checking
  • Required-section presence checks per template type
  • Code block syntax validation
  • GitHub Actions workflow included out of the box

sequenceDiagram autonumber participant DEV as Developer participant TL as Template Library participant APF as AI Prompt Framework participant VAL as Validation System participant PR as Pull Request DEV->>TL: Select documentation template TL-->>DEV: Markdown template with placeholders DEV->>APF: Apply AI prompt to fill template APF-->>DEV: AI-generated draft content DEV->>DEV: Review and edit AI draft DEV->>PR: Open documentation pull request PR->>VAL: Trigger CI validation workflow VAL-->>PR: Schema, links, structure checks PR-->>DEV: Review feedback and approval
Incremental adoption: Teams can adopt any single subsystem independently. A team might start with just the Template Library (Subsystem 1) and gradually add the AI Prompt Framework (Subsystem 3) and Validation System (Subsystem 5) as their workflow matures.
