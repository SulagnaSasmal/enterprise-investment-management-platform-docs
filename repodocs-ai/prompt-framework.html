AI Prompt Framework

The AI Prompt Framework is a structured library of prompt templates designed to generate high-quality technical documentation using AI language models. Unlike ad-hoc AI prompting, RepoDocs AI prompts are engineered with context blocks, output-format constraints, guardrails, and review checkpoints that keep generated content grounded, consistent, and safe to merge.

Guardrail principle: Every prompt in the framework includes an explicit instruction to cite only information provided in the context block. AI-generated content is always reviewed by a human before it is marked status: published in the metadata schema.

Prompt anatomy

Every RepoDocs AI prompt follows a five-block structure:

1. Role block
Establishes the AI persona. Always a senior technical writer familiar with SaaS API documentation conventions.
2. Context block
Injects the source material: API spec (OpenAPI), code comments, existing documentation, or architecture notes. This is the only factual source the AI may use.
3. Task block
Specifies the exact documentation artifact to produce: endpoint reference, error code catalogue, getting started guide, etc.
4. Format block
References the exact template from the Template Library. Instructs the AI to fill placeholders without changing section structure.
5. Guardrail block
Explicit constraints: do not invent parameters not in the context, flag any ambiguities with [REVIEW NEEDED], use second-person imperative for instructions.

Sample prompt — API endpoint reference

### ROLE
You are a senior technical writer specialising in SaaS API documentation.

### CONTEXT
The following is the OpenAPI specification for the endpoint you will document.
Only use information present in this context. Do not invent fields, parameters,
or behaviour not listed here.

```yaml
{{OPENAPI_ENDPOINT_YAML}}
```

### TASK
Write the complete API reference documentation for this endpoint.
Cover: description, authentication, path parameters, query parameters,
request body, response schema (200 and all error codes), and a curl example.

### FORMAT
Use the RepoDocs AI endpoint reference template exactly. Fill all
{{PLACEHOLDER}} tokens. Do not add or remove sections.
Include the YAML front-matter block with status: draft.

### GUARDRAILS
- If a field's purpose is ambiguous, write [REVIEW NEEDED: describe ambiguity].
- Do not infer default values not stated in the spec.
- Use second-person imperative voice for all instructions ("Call this endpoint to...").
- Keep descriptions to one sentence per parameter unless a second sentence
  is essential for correct usage.

AI generation workflow

flowchart TD SOURCE[Source material\nOpenAPI spec / code / notes] --> INJECT[Inject into context block] INJECT --> SELECT[Select prompt template\nfrom prompt library] SELECT --> RUN[Run prompt via AI tool\nCopilot / OpenAI / Claude] RUN --> DRAFT[AI-generated draft\nwith REVIEW NEEDED markers] DRAFT --> HUMAN[Human review\nResolve markers, verify facts] HUMAN --> STATUS{Accurate and\ncomplete?} STATUS -->|Yes| PUBLISH[Set status: review\nOpen pull request] STATUS -->|No| REFINE[Refine context\nor edit manually] REFINE --> RUN

Review checklist

After AI generation, the author reviews the draft using this checklist before opening a pull request:

  • All [REVIEW NEEDED] markers resolved or removed
  • Every parameter name matches the actual API implementation
  • All code examples are syntactically correct and can be copy-pasted
  • Error codes are complete — no codes from the implementation are missing
  • Authentication instructions match the current auth mechanism
  • YAML front-matter status updated from draft to review
  • No sensitive information (internal URLs, credentials, internal codenames) included

Diagram Templates

The Diagram Templates subsystem provides Mermaid.js and PlantUML starter diagrams for the most common technical documentation diagram types. Templates are embedded directly in Markdown and render natively in GitHub pull request previews, Docusaurus, MkDocs, and GitBook.
