SunBridge Asset Atrium Manager

Database & configuration management
Oracle schema versioning, reference data, and cache management

Summary

This section describes the database schema management, reference data configuration, and cache lifecycle patterns used by Asset Atrium Manager. The platform runs on Oracle 19c RAC with schema versioning managed through Liquibase changesets applied during release deployments.

Core data model areas

  • Fund & portfolio structure: fund master, sub-fund hierarchy, strategy/sleeve decomposition, benchmark associations
  • Instrument master: security reference data, pricing identifiers (ISIN, SEDOL, Bloomberg ticker), corporate action entitlements
  • Counterparty & SSI data: broker records, custodian accounts, standard settlement instructions per instrument type
  • Processing zone configuration: zone master, fund-zone mapping, market calendars, NAV cut-off schedules
  • Audit tables: event processing audit, compliance decision log, user action history

Schema versioning (Liquibase)

  • All DDL changes managed via Liquibase XML changesets checked into version control.
  • Changesets follow expand-migrate-contract pattern for zero-downtime compatibility.
  • Pre-deployment validation: Liquibase dry-run in UAT before production execution.
  • Rollback scripts maintained for every changeset; tested as part of release qualification.

Reference data management

  • Fund setup: new fund onboarding via Asset Atrium Admin console; requires zone assignment, calendar selection, fee schedule, compliance ruleset.
  • Instrument master updates: daily ingest from Bloomberg BVAL reference data feed; manual override capability for OTC instruments.
  • Calendar maintenance: annual calendar load from exchange-published holiday schedules; ad-hoc updates for unscheduled market closures.
  • SSI updates: custodian SSI changes routed through maker-checker workflow with 4-eye approval.

Oracle Coherence cache invalidation

  • Configuration change events: fund setup changes, SSI updates, and calendar modifications trigger targeted Coherence cache invalidation via JMS event.
  • Batch milestone events: pricing ingestion complete, NAV calculated, and historization complete trigger cache refresh for dependent data regions.
  • Date rollover events: business date advance invalidates all date-sensitive cache entries (settlement calendars, order validity, dealing deadlines).

Environment configuration

  • WebLogic JNDI: datasource, JMS queue, and external endpoint configurations managed per environment (DEV, UAT, PROD).
  • Feature flags: new features can be enabled per fund, per zone, or globally via configuration table; no code deployment required for flag changes.
  • Sensitive credentials: Oracle wallet and WebLogic credential store for database passwords, SWIFT keys, and Bloomberg API tokens.
All reference data changes in production require change management approval (ServiceNow CR) and are applied during designated maintenance windows unless classified as emergency changes.
